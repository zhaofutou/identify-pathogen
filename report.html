Part I — Salmonella Genome Assembly

What Was the Task?

We received two Illumina paired-end FASTQ files from a Salmonella strain sequencing run and were asked to assemble the genome. This is a classic de novo genome assembly problem — reconstructing the full bacterial chromosome from millions of short (150bp) DNA fragments.

🤔 The Challenge: Windows + Bioinformatics

Here's the problem: SPAdes (the gold-standard bacterial genome assembler) doesn't have a Windows build. Neither do most bioinformatics tools — they're all designed for Linux. Our options were:

  • VPS (Debian 13) — only 1GB RAM, 2 cores. Way too weak for genome assembly.
  • WSL2 — runs Linux natively on the Windows kernel. Access to all 16 CPU cores and 64 GB DDR5 RAM. ✅ This is the answer.

We enabled WSL2 (one-time reboot), installed Ubuntu 26.04, and had a full Linux bioinformatics environment running in minutes.

🔑 The Critical Question: Assembly vs. Direct Mapping?

This is where the outbreak investigation differs fundamentally from the Salmonella genome assembly:

APPROACH A (Part I — Assembly) Reads → Assemble contigs → Compare to database Goal: Reconstruct the complete genome from scratch When: You have a pure culture (single organism) Tools: SPAdes (De Bruijn graph assembly) APPROACH B (Part II — Direct Mapping) ← WE USED THIS Reads → Map directly to pathogen references → Count hits Goal: Identify which pathogens are present When: You have a metagenomic sample (mixed organisms) Tools: minimap2 + curated reference panel

In a real outbreak, stool samples contain the patient's own gut bacteria, food remnants, and potentially the pathogen. You don't assemble — you ask: "Which of my known pathogens have reads mapping to them?"

Step 2: Map Reads Against Every Reference

For each sample × pathogen combination, we ran:

# 1. Map Nanopore reads to reference genome
minimap2 -ax map-ont -t 8 --eqx reference.fasta sample.fastq > sample.sam

# 2. Convert to sorted BAM
samtools sort -@ 4 -o sample.bam sample.sam

# 3. Calculate mapping statistics
samtools flagstat sample.bam    # Total/mapped reads
samtools depth sample.bam       # Per-position depth

This is NOT assembly — we're asking each read: "Do you look like Salmonella? E. coli? Adenovirus?" and counting how many say yes.

Step 3: Score and Rank

For each pathogen, we calculate three metrics:

  • Mapping rate — what % of reads match this pathogen? (higher = more pathogen DNA present)
  • Average depth — how many times is each position covered? (deeper = more confident)
  • Genome coverage — what % of the reference genome has at least 1 read? (100% = complete pathogen genome present)

A true pathogen will have all three high. Background noise (cross-mapping to related species) will have low mapping rate and partial coverage.

🔍 VERDICT: Adenovirus 40

The most likely causative agent of this diarrhea outbreak is Human Adenovirus Serotype 40 (Enteric Adenovirus). It was detected with extremely high confidence (1,357× depth, 100% genome coverage) in both clinical and food samples, confirming foodborne transmission.

Adenovirus 40/41 is a leading cause of acute gastroenteritis in children under 5 worldwide. It's transmitted via the fecal-oral route, often through contaminated food or water. The virus is non-enveloped (resistant to many disinfectants) and can persist on surfaces.

The Technology Deep-Dive

Why No Assembly Was Needed

In the Salmonella project, we assembled because we had a pure culture — one organism, millions of reads from just that one genome. Assembly makes sense there.

In the outbreak investigation, each stool sample is a metagenomic soup: the patient's gut bacteria (trillions), food remnants, environmental organisms, and hopefully — the pathogen. Assembling this mess would be:

  • Extremely slow (hours to days)
  • Confusing (which contig is the pathogen?)
  • Wasteful (you'd assemble the patient's E. coli instead of the virus you're looking for)

Direct mapping is faster, simpler, and more sensitive for pathogen detection. You ask a specific question: "Is Salmonella here?" and get a quantitative answer.

Online Database vs. Local Database

We used an on-the-fly approach: reference genomes are downloaded from NCBI's E-utilities API each time a new pathogen is tested.

ApproachProsCons
On-the-fly (ours)No setup, always current, small footprintSlightly slower per run
Kraken2/centrifuge (pre-built DB)Extremely fast classification, unbiasedRequires 5-50 GB database download
Custom local DBTailored to your needs, no internet neededMust maintain/update yourself

For a production outbreak lab, you'd use Kraken2 or centrifuge with a pre-built database for speed. Our approach is better for demonstration because it's transparent — you can see exactly which references were tested.
